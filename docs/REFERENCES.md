# 成果与政策参照

以下材料用于定义产品边界和技术可行性，不代表本演示站点已完成临床验证、法定等级认定或政府平台对接。

## 能力评估与照护框架

1. [GB/T 42195-2022《老年人能力评估规范》](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=D8A0B4F27794EC73C511F1B948103256)

   国家标准全文公开系统显示该标准现行，由民政部主管，规定老年人能力评估的指标与评分、组织实施及评估结果。本项目借鉴其“结构化维度、规范组织、结果留痕”思路，但没有复制受限量表全文，当前规则只是比赛演示规则。

2. [WHO Integrated Care for Older People (ICOPE) implementation framework](https://www.who.int/publications/i/item/9789241515993)

   ICOPE 强调以人为中心、围绕老年人内在能力变化开展综合评估和照护衔接。本项目据此把运动、感官、认知、心理和日常生活支持放在同一年度检查流程中。

3. [WHO ICOPE 2025 person-centred assessment guidance](https://www.who.int/publications/i/item/9789240103726)

   新版指导继续强调由健康和照护工作者实施的以人为中心评估。对本项目的直接约束是：AI只能辅助采集和整理，人员必须确认并负责后续处置。

## 可落地技术组件

4. [ModelScope FunASR](https://github.com/modelscope/FunASR)

   FunASR 是开源语音识别工具包，覆盖离线/流式 ASR、VAD、标点等能力，可作为生产版普通话及本地方言适配候选。方言或广西口音仍需本地授权样本验证；低置信度必须回到人工修正，不能直接进入评分。

5. [MediaPipe Pose](https://chuoling.github.io/mediapipe/solutions/pose.html)

   MediaPipe Pose 可从视频估计人体关键点，可用于动作完成度和画面质量的辅助观察。它不是老人能力等级模型，遮挡、辅具、轮椅和个体差异都要求人工兜底。

6. [Web Speech API](https://developer.mozilla.org/docs/Web/API/Web_Speech_API)

   浏览器的语音识别与语音合成可快速实现比赛原型。本项目只把它作为渐进增强能力，不保证所有浏览器可用，识别不可用时可直接手输。

## 隐私与伦理边界

7. [《中华人民共和国个人信息保护法》](http://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)

   第二十八条将生物识别、医疗健康等列为敏感个人信息。生产版应证明特定目的和充分必要性，取得单独同意并采取严格保护措施。

8. [国家网信办：敏感个人信息保护解读](https://www.cac.gov.cn/2021-09/08/c_1632692967456129.htm)

   用于落实最小必要、单独同意、严格保护和信息主体权利。架构中的“音视频可跳过、默认不保存、监管只上行脱敏聚合”由此形成。

## 本项目采用的落地结论

- 不等待“中国本土老人明显情绪标签数据集”，也不训练情绪诊断模型。
- 广西语言标签只记录“普通话、地方口音普通话、方言或民族语言、未知/不愿填写”及自愿备注，仅用于 ASR 质控。
- 优先采集固定任务和可观察结果，允许语音转文字、老人自填、护理人员代录和历史导入。
- 危机线索只触发人工处置，不由模型给出心理诊断。
- 生产试点先验证完成率、耗时、ASR 修正率、缺项率和人员一致性，再讨论模型优化。
