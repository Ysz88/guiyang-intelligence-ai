# 系统架构说明

## 产品范围

主流程是养老机构内对老人开展年度能力检查，覆盖肢体活动、言语沟通、视听能力、心理与认知、日常生活能力五个维度。系统只额外生成机构级脱敏监管摘要，不扩张为跨部门综合监管平台。

## 责任链

```text
摄像头/麦克风/触屏/代录/历史导入
  -> AI或浏览器适配器生成结构化草稿
  -> 检查人员逐字段确认
  -> 确定性规则引擎计算关注等级
  -> 检查或复核人员确认结果
  -> 个人、机构、脱敏监管输出
```

AI 只能转写、播报、整理字段和提示冲突，不能导入或调用 `src/rules/engine.ts`。规则引擎只读取确认后的结构化数据，不能自行补齐缺项。最终确认必须记录人员、时间和必要说明。

## 可替换适配器

演示版优先使用浏览器能力，生产版可在不改变规则引擎的前提下替换：

- 语音识别：浏览器 `SpeechRecognition`、FunASR、faster-whisper 或 sherpa-onnx。
- 语音播报：浏览器 `speechSynthesis` 或机构内网 TTS。
- 动作辅助：MediaPipe Pose/Hands 或完全由人员现场观察。
- 大模型：固定问题、白名单追问、Schema 校验的 JSON 输出。

任何适配器失败、低置信度、噪声、遮挡或老人拒绝音视频时，都允许切换到触屏或护理人员代录。识别置信度与语言背景只能产生质量提醒，不能改变等级。

## 数据与隐私

演示版在浏览器内确定性生成 60 条模拟记录并写入 `localStorage`。仓库不包含真实姓名、联系方式、老人音视频、医疗健康档案、模型权重或 API 密钥。

生产版至少需要：

- 单独告知和知情同意，可撤回并可跳过音视频。
- 最小必要字段、用途限制、保存期限和删除机制。
- 角色权限、加密传输与存储、访问和变更审计。
- 音视频默认不长期保存；确需保存时另行授权并设置期限。
- 监管侧只接收机构计数、完成率和等级分布等脱敏聚合字段。

## 规则策略

每个维度包含 3 或 5 个任务，每项由检查人员记录 0-3 档。规则包括缺项拒判、有效任务不足转人工、单项高关注托底、总体取五维最高档、三个及以上 2 档升级、危机停算、冲突复核、未同意或未确认拒判。规则版本、命中规则、质量提醒和人工说明均随记录保存。

当前分段是竞赛演示规则，不等同于国家标准原文或法定等级。生产试点应由养老服务专业人员依据适用规范校准，并形成受控的规则发布流程。

## 演示与生产部署

| 能力 | 演示版 | 生产版替换项 |
| --- | --- | --- |
| 身份 | 固定演示检查员 | 机构账号、角色和最小权限 |
| 数据 | 浏览器 `localStorage` | 加密数据库、备份恢复、留存策略 |
| ASR/TTS | 浏览器 API | 内网或合规服务，记录组件版本 |
| 姿态 | 实时摄像头预览与人工质量值 | 经验证的姿态组件或纯人工观察 |
| 大模型 | 不依赖外部模型即可演示 | 私有或合规模型，只输出结构化草稿 |
| 审计 | 本地确认时间和说明 | 不可抵赖日志、审批与规则版本管理 |
| 监管 | 下载脱敏 JSON 契约 | 经主管方确认的数据标准和接口 |
